## 67.1 之前的错误结论

**docs/55 和之前的分析都写：**

```
「游戏启动时只加载 InitBundle（0CE8FA57）」
「7064D8E2 的 main bundles 启动时完全不加载」
```

**这个结论是【错误的】。**

## 67.2 错误原因

**采样太早。** 之前的 `/proc/<pid>/fd` 采样只跑了 18 秒：

```
[3s]  .chk = 0
[6s]  .chk = 0
[9s]  .chk = 1   ← 这里只看到 1 个就停了
[18s] .chk = 1
```

**实际跑满 60 秒后：**

```
[60s] 打开的 .chk = 11 个
```

## 67.8 ★★ 后续分析：3 个都是音频组

**用 `vfsfull` 解析各组 `.blc` 得到的组名：**

| 组 | 组名 | 内容 | 大小 |
|---|---|---|---|
| `0CE8FA57` | **InitBundle** | 启动资源包 | 208 MB |
| `24ED34CF` | **Audio** | 音频 | 3.6 GB |
| `E1E7D7CE` | **AudioChinese** | 中文语音 | 1.3 GB |
| `F151B649` | **HotfixAudio** | 热更新音频 | 6.8 MB |

**⇒ 启动时加载的 4 个组中，3 个是【音频】**

**⇒ 非音频资源【确实只来自 InitBundle（0CE8FA57）】**

## 67.9 结论修正（二次）

```
第一次结论（对）: 启动只加载 InitBundle 的非音频资源
第二次结论（错）: 启动加载多个组 ⇒ 纹理可能在别的组
第三次结论（对）: 其他组都是音频 ⇒ 纹理确实只在 InitBundle

⇒ 最终确认：启动画面纹理在 0CE8FA57（InitBundle）里
⇒ 之前替换 4 个纹理不显示，不是"选错组"，而是别的原因
```

## 67.10 剩余可能性（为什么 4 个纹理不渲染）

```
① 这 4 个纹理在启动画面确实不用（只是被解析，没被绘制）
② .blc 的 dataMd5 校验导致游戏跳过修改过的文件
③ 纹理需要特定 UI 状态才绘制

排除: 选错组 ✗（确认只在 InitBundle）
排除: 流光偏移错 ✗（已用正确偏移 14768/18160/18256/22312）
排除: 容器损坏 ✗（目标区验证 TRUE）
排除: 游戏崩溃 ✗（60 秒零崩溃）
```
