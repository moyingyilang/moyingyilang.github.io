把一个 Kotlin/Compose 的桌面界面复刻成 QML 时，我原以为时间会花在"把每个界面画出来"。
实际最花时间的是下面三件事，而且它们的共同点是：**报错信息完全没指向真正的病因**。

## 一、编译期绑定读不到运行时注入的属性

为了让 QML 能显示一张在 C++ 侧生成的图片，我把图片路径通过"上下文属性"注入给 QML。
结果运行时报：

```
TypeError: Cannot read property 'pageSeq' of null
```

诡异之处在于：**同一个对象，用别的方式访问完全正常** —— 在 `Component.onCompleted` 里打印
`backend.pageSeq` 能打出 0，信号回调、方法调用也都正常，只有**绑定**里读它是 null。

排查路径（记录一下，因为每一步都排除掉了一类常见猜测）：

1. 怀疑元对象（moc）没生成 -> 检查生成文件，属性名在里面，**排除**；
2. 怀疑 moc 过期 -> 对比时间戳，比头文件新，**排除**；
3. 怀疑布局或对象生命周期 -> 运行时打印对象状态，正常，**排除**；
4. 结论：**QML 被编译成字节码后，编译期生成的绑定无法解析运行时注入的上下文属性**，
   而函数体与信号回调是运行时求值，所以不受影响。

**修法**：不要在绑定里直接读上下文属性。把计算放进信号回调，结果写进**被绑定对象的属性**：

```text
绑定式写法（坏）：visible: backend.pageSeq > 0
回调式写法（好）：Connections { target: backend; function onPageChanged() { root.reading = backend.pageSeq > 0 } }
                  ...
                  visible: root.reading
```

## 二、布局：一个面板只分到 2 像素

另一处症状是"图片明明加载成功了，界面却看不到它"。日志显示：

```
阅读页已显示：源 852x1280，实际绘制 0x0
几何：右栏 2x780
```

右栏面板只拿到 **2 像素宽**（恰好等于布局间距，说明它分配到的宽度是 0），
而左侧栏写的明明是"首选宽度 380"。

原因：**首选宽度会被子项的隐式/最小宽度顶掉**。侧栏内部有一个用"父宽度"作为自身宽度的
列表项，形成了一条自引用链，导致侧栏的最小宽度被撑到接近整个窗口。

**修法**：固定宽度的侧栏要同时设最小与最大宽度（`minimumWidth` / `maximumWidth`），
而不是只设 `preferredWidth`。改完实测 `左栏 380，右栏 800`。

**方法论提醒**：这个问题我先误判过两次（以为是可见性切换、以为是面板嵌套），
最后一次是靠自己加的"布局探针"——启动 3 秒后打印各层宽度——才定位到具体是哪一层。
**当症状是"看不见"时，先想办法把尺寸量出来，再谈猜测。**

## 三、构建：Makefile 让每次构建都重编，Ninja 不会

界面本身跑通后，我发现一件更浪费的事：**每次 `cmake --build`，哪怕一行代码都没改，
都要 13~25 秒**，而且连续三次都是如此。

根因是 QML 缓存（由 `qmlcachegen` 生成的那个 `.cpp`）的依赖里包含类型注册产物
（`.qmltypes`、`.qrc`）与工具本身；只要上游的"类型注册"步骤重跑，这条链就整体重跑。
Makefile 生成器对这类"生成文件依赖生成文件"的场景处理不好。

**换 Ninja 直接解决**：无改动时输出 `ninja: no work to do.`，耗时 **0.04 秒**。
换生成器只需重新配置构建目录，`cmake --build build`、测试命令、脚本里的可执行文件路径都不用改。

顺手接上 ccache 后，**清空重建**也从 72.5 秒降到 13 秒 —— 但要注意账要算两次：

| 场景 | 耗时 |
| --- | --- |
| 无 ccache 清空重建 | 72.5 秒 |
| 有 ccache，首次（填充缓存） | 99.4 秒 |
| 有 ccache，缓存热 | 13.0 秒 |

也就是说：如果你只构建一次，它反而更慢；如果反复重建，它每次省约 60 秒。
另外 `CMAKE_CXX_COMPILER_LAUNCHER` 必须设在 `project()` **之前**才生效。

## 结语

这三个坑的共同教训：

1. **报错信息未必指向病因**（"属性为 null"的真因是编译期绑定）；
2. **看不见的问题要先变成可测量的量**（尺寸、绘制尺寸、命中数）；
3. **工具链的选择本身就是优化**（生成器、缓存），而且往往比改代码见效快。

移植一个界面真正的工作量，很大一部分不在界面里。
